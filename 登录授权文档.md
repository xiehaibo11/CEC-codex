## 结论

网站要接入 Google / GitHub 登录，推荐链路是:

```text
用户 -> www.bocail.com/login -> Google/GitHub -> auth.bocail.com/callback -> Casdoor -> www.bocail.com/callback -> 前端保存 token
```

前端按钮使用 Casdoor 标准 OAuth 授权地址:

```text
https://auth.bocail.com/login/oauth/authorize?...&provider_hint=github_login
https://auth.bocail.com/login/oauth/authorize?...&provider_hint=google_login
```

`provider_hint` 只负责让 Casdoor 直接跳到对应的第三方授权页，最终应用回调仍然必须是 `https://www.bocail.com/callback`。

不要让前端直接保存或使用 Google / GitHub Client Secret。Google / GitHub 的 Secret 只填在 Casdoor Provider 里。

## 两个 Callback 的区别

这里最容易配错，必须按下面填:

```text
Google / GitHub 后台 Authorization callback URL:
https://auth.bocail.com/callback
```

```text
Casdoor Application Redirect URL:
https://www.bocail.com/callback
```

原因:

- 第三方 OAuth Provider 先回调到 Casdoor。
- Casdoor 登录成功后，再把用户带回网站前端。
- 如果 Google / GitHub 后台填成 `https://www.bocail.com/callback`，Casdoor 收不到第三方回调。
- 如果 Casdoor Application Redirect URL 填成 `https://auth.bocail.com/callback`，用户登录后回不到网站。

官方参考:

- Casdoor Application config: https://casdoor.org/docs/application/config
- Casdoor Google OAuth: https://casdoor.org/docs/provider/oauth/google/
- GitHub OAuth App callback: https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app
- Google OAuth redirect URI: https://developers.google.com/identity/protocols/oauth2/web-server

## 当前报错说明

`报错.md` 里的错误:

```text
get-application:1 Failed to load resource: the server responded with a status of 500 ()
Unexpected end of JSON input
```

含义:

- 认证服务接口返回了 500。
- 返回体为空或不是 JSON，前端执行 `response.json()` 时触发 `Unexpected end of JSON input`。
- 这不是 Google / GitHub 凭证本身的典型错误。
- 需要优先确认 Casdoor 是否已部署、`auth.bocail.com` 是否能访问、后端 `AUTH_PROXY_UPSTREAM` 是否指向正确 Casdoor。

`manifest.json start_url ignored` 和登录主链路关系不大，可后置处理。

## Casdoor 配置

### Application

创建或编辑 Casdoor Application:

```text
Name: hyper-alpha-arena
Organization: built-in
Redirect URL: https://www.bocail.com/callback
```

创建完成后，复制 Casdoor Application 的 Client ID，写入服务器环境变量:

```text
AUTH_CLIENT_ID=41837caf0514413bb14b
```

注意:

- 这里的 `AUTH_CLIENT_ID` 不是 Google Client ID。
- 这里的 `AUTH_CLIENT_ID` 不是 GitHub Client ID。
- 它必须是 Casdoor Application 生成的 Client ID。

### Google Provider

Category: OAuth
Type: Google
Name: google_login
Client ID: GOOGLE_CLIENT_ID_REDACTED

## 服务器环境变量

宿主机部署使用:

```text
/etc/hyper-alpha-arena.env
```

正式切到 `auth.bocail.com` 后应配置:

```env
AUTH_PROXY_UPSTREAM=https://auth.bocail.com
AUTH_PROVIDER=https://auth.bocail.com
AUTH_PROXY_PROVIDER=https://www.bocail.com
AUTH_CLIENT_ID=41837caf0514413bb14b
AUTH_APP_NAME=hyper-alpha-arena
AUTH_ORGANIZATION_NAME=built-in
AUTH_REDIRECT_PATH=/callback
AUTH_GITHUB_PROVIDER_NAME=github_login
AUTH_GITHUB_CLIENT_ID=Ov23liwdTwGyhQkcFrYK
AUTH_GOOGLE_PROVIDER_NAME=google_login
AUTH_GOOGLE_CLIENT_ID=GOOGLE_CLIENT_ID_REDACTED
```

修改后重启:

```bash
systemctl restart hyper-alpha-arena.service
```

## 上线前检查

1. DNS:

```bash
getent hosts auth.bocail.com
```

必须返回:

```text
102.204.223.50 auth.bocail.com
```

2. Casdoor HTTPS:

```bash
curl -I https://auth.bocail.com
```

应返回 HTTP 200 或 302，不能是 DNS 错误、证书错误或连接失败。

3. 网站配置:

```bash
curl -fsS https://www.bocail.com/auth-config.json
```

确认 `authProvider` 是:

```text
https://auth.bocail.com
```

确认 `clientId` 是 Casdoor Application Client ID: `41837caf0514413bb14b`。

4. 后端认证代理:

```bash
curl -fsS "https://www.bocail.com/api/get-app-login?application=hyper-alpha-arena"
```

正常情况下应返回 JSON。不能返回空响应或 500。

5. 登录页:

```text
https://www.bocail.com/login
```

页面应显示:

```text
Continue with GitHub
Continue with Google
```

点击后应跳到 GitHub 或 Google 授权页。

## 常见错误

### redirect_uri_mismatch

优先检查:

```text
Google / GitHub 后台 callback 是否是 https://auth.bocail.com/callback
```

不要填:

```text
https://www.bocail.com/callback
```

### get-application 500

优先检查:

```text
AUTH_PROXY_UPSTREAM
Casdoor 服务状态
auth.bocail.com DNS
auth.bocail.com HTTPS
Casdoor Application 是否存在 hyper-alpha-arena
```

### 登录成功后回不到网站

优先检查 Casdoor Application:

```text
Redirect URL: https://www.bocail.com/callback
```

### 前端 auth-config 仍然显示旧 account.akooi.com

检查:

```bash
systemctl show hyper-alpha-arena.service -p EnvironmentFiles
cat /etc/hyper-alpha-arena.env
systemctl restart hyper-alpha-arena.service
```
