# 第 01 课：量化交易全景图

## 一个典型场景（示意）

一位量化交易者开发了基于机器学习的美股策略，回测年化收益80%，夏普比率2.5。投入50万美元后，前两个月表现完美，账户增长30%。但市场进入震荡期后，策略开始反复被打脸，三个月后账户回撤40%。

**问题根源**：不是模型不够好，而是"一个模型无法同时擅长所有市场状态"。趋势市需要动量策略，震荡市需要均值回归，危机市需要风控优先。这是结构性矛盾。

## 1.1 量化交易的三个层次

### 按资金规模和竞争维度划分

| 层次 | 典型资金 | 核心竞争力 | 代表玩家 |
|------|---------|----------|--------|
| 高频做市 | $1B+ | 速度（微秒级）、硬件、交易所关系 | Citadel Securities, Virtu, Jump |
| 机构量化 | $100M-$10B | 研究深度、因子挖掘、风控体系 | Two Sigma, DE Shaw, 幻方、九坤 |
| 中小型/个人 | <$100M | 灵活性、细分市场、执行纪律 | 小型对冲基金、自营交易者 |

### 第一层：高频做市（你打不过的对手）

**他们做什么**：在买卖价差中赚取利润，利用微秒级信息优势套利，每天交易数百万笔。

**为什么你打不过**：
- 你的订单延迟：50-100毫秒（普通网络）
- 他们的延迟：5-50微秒（交易所托管）
- 差距：1000-10000倍

**结论**：除非拥有数亿资金和顶级技术团队，否则不要碰高频。这是军备竞赛，散户必输。

### 第二层：机构量化（本书的学习目标）

**他们做什么**：中低频策略（持仓小时到数周），多因子模型、统计套利、事件驱动。

**为什么值得学**：
- 不依赖速度优势，靠策略和风控取胜
- 方法论可复制，适合系统性学习
- 多智能体架构的主要应用场景

### 第三层：中小型/个人

**优势**：灵活性高、可做大机构看不上的小容量策略

**劣势**：数据和研究资源有限、容易情绪化交易

## 1.2 主要策略类型

### 六大策略类型

| 策略类型 | 核心逻辑 | 持仓周期 | 难度 |
|---------|--------|--------|------|
| 高频做市 | 赚买卖价差，提供流动性 | 秒-分钟 | ★★★★★ |
| 统计套利 | 相关资产价差回归 | 分钟-天 | ★★★★ |
| 趋势跟随 | 价格动量持续性 | 天-周 | ★★★ |
| 均值回归 | 价格偏离后回归 | 小时-天 | ★★★ |
| 事件驱动 | 财报、并购等事件 | 天-月 | ★★★★ |
| 多因子 | 组合多个Alpha因子 | 周-月 | ★★★★ |

### 策略的生命周期

**重要认知**：没有永远有效的策略。

```
发现 → 验证 → 部署 → 衰减 → 退役
```

你的系统必须能**持续进化**——这就是为什么需要多智能体架构。

## 1.3 为什么需要多智能体架构

### 单一模型的致命缺陷

| 市场状态 | 最佳策略 | 单一模型的问题 |
|---------|--------|--------------|
| 趋势市 | 动量策略：顺势加仓 | 震荡市会被反复打脸 |
| 震荡市 | 均值回归：高抛低吸 | 趋势市会错过大行情 |
| 危机市 | 风控优先：减仓避险 | 可能在暴跌中满仓硬扛 |

**核心问题**："一个模型无法同时擅长所有状态"。这是结构性缺陷，调参解决不了。

### 多智能体的解决思路

**三个核心设计原则**：

1. **专家分工**：不同Agent负责不同市场状态，各自做到极致
2. **动态路由**：Meta-Agent判断当前市场状态，分发给对应专家
3. **风控独立**：Risk Agent拥有一票否决权

### 常见误区

| 误区 | 事实 |
|-----|------|
| "多智能体就是多跑几个模型" | 关键是**协作机制**：谁说了算？ |
| "单一模型调参调到极致也行" | 市场状态是**结构性变化**，不是噪声 |
| "Agent会自动赚钱" | Agent是工具，Alpha来自策略设计和风控纪律 |
| "量化就是预测价格" | 量化是**管理风险下的收益** |

### 多智能体的适用边界

| 失效场景 | 原因 |
|---------|------|
| 市场状态切换太快 | Meta-Agent识别滞后 |
| 状态边界模糊 | 趋势和震荡交替出现 |
| 协调成本 > 收益 | 简单市场用复杂架构 |

**核心原则**：多智能体的价值在于"跨状态的稳健性"。

## 1.4 多智能体协作示例

### 关键协作模式

| 模式 | 说明 | 适用场景 |
|-----|------|--------|
| Chain (链式) | Agent A → B → C，顺序执行 | 有明确依赖关系的任务 |
| DAG (并行) | 多个Agent同时执行，结果汇总 | 独立子任务 |
| Debate (辩论) | 多个Agent给出不同观点 | 多角度分析决策 |
| Reflection (反思) | Agent检查自己或他人输出 | 提高输出质量 |
